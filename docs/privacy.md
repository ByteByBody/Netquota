# NetQuota privacy and transparency

NetQuota is designed for a household administrator to monitor internet usage on
devices they are responsible for. It is intentionally not a covert monitoring
tool. Every agent discloses what it collects, and every user can see whether
monitoring is running.

## Data collected

Only what is needed to attribute usage and manage devices:

- **Byte counters**: total bytes received and sent since a baseline, per selected
  network interface. On iOS, only this app's own request bytes.
- **Device metadata**: name, platform, agent version, measurement scope/quality.
- **Timing**: when samples are observed and received, and last-seen time.
- **Events**: threshold crossings, stale-agent warnings, enrollment and device
  management actions.
- **Administrator account**: username and a PBKDF2 password hash.

## Data explicitly NOT collected

- Browsing history, visited websites, or URLs.
- Packet contents or deep-packet inspection.
- Application-level activity or per-app usage.
- Location, contacts, messages, photos, or any unrelated personal data.
- Router or ISP credentials.
- Any content of network traffic.

NetQuota does not use packet interception, private APIs, jailbreaks, or an
undeclared VPN configuration.

## Consent and visibility

- Enrollment requires a single-use code generated by the administrator.
- The mobile apps show a plain-language consent screen **before** enrollment and
  a permanent status screen showing monitoring state, last successful report, and
  the agent's reporting sequence.
- Device users can pause monitoring at any time from the app. Pausing stops
  reporting immediately.
- The dashboard names each device by platform and marks devices that report only
  partial coverage.

## Credentials

- Device credentials are high-entropy tokens stored in OS secure storage:
  Windows Credential Manager / Secret Service via `keyring` (desktop, with a
  restricted 0600 file fallback), Android Keystore-backed
  `EncryptedSharedPreferences`, and iOS Keychain.
- The server stores only a hash of the credential; the raw token is returned once,
  at enrollment, and never through the dashboard.
- Revoking a device rotates and invalidates its credential immediately.

## Revocation and uninstall

Administrator side:
1. Open the device in the dashboard and select **Revoke device**. Its credential
   stops working at once.
2. Optionally delete the device to remove it from listings. Historical usage is
   retained for accounting integrity unless the group is deleted.

Device side:
- **Windows**: run `packaging/uninstall-windows.ps1`. Use `-PurgeData` to delete
  local config/credential. Removing the app does not delete server-side history.
- **Linux**: `sudo systemctl disable --now netquota-agent && sudo rm -f
  /etc/systemd/system/netquota-agent.service`, then remove `/opt/netquota` and,
  if desired, `/var/lib/netquota`.
- **Android**: use **Forget this device** in the app, then uninstall.
- **iOS**: use **Forget this device**, then delete the app.

Always revoke the device on the server as well; removing an app never tells the
server to stop expecting reports, and revocation is what invalidates the
credential.

## Server-hardening guidance

The management API is for the home network, not the public internet.

- Bind the API to loopback (the compose file publishes `127.0.0.1:8000` only) and
  put Caddy in front for TLS.
- Use a HTTPS certificate trusted on your devices: Caddy's internal CA, a private
  CA, or a real domain with ACME. Import the CA into device trust stores.
- **Never** expose PostgreSQL publicly. It is not published in the compose file.
- Set strong `POSTGRES_PASSWORD`, `JWT_SECRET`, and `ADMIN_PASSWORD`.
- Rate limiting is in-process (single instance). For multi-instance deployments,
  move it to Redis.
- Remote access, if ever needed, should go through a VPN (e.g. WireGuard/Tailscale)
  rather than exposing the API publicly. This is out of scope for the MVP.
- Back up the database regularly; see `docs/architecture.md`.

## Honest measurement statement

Displayed totals are **device-reported usage**, not guaranteed ISP-billed usage.
Interface selection excludes virtual adapters to avoid double counting, but no
software agent can guarantee it matches the provider's meter exactly. iOS in
particular cannot measure whole-device usage with public APIs; its figures are
app-only and clearly marked as partial.
